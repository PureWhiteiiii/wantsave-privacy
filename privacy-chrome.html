我全都要 WantSave · Chrome 基础版 1.1.0

隐私政策

发布者：WantSave · 生效日期：2026-10-20 · 更新日期：2026-10-21

WantSave 在你的浏览器中发现、下载和合并媒体，并保存本地任务以便恢复。扩展没有发布者运营的媒体上传或行为统计服务。本网站由 GitHub Pages 托管；你主动发送的支持邮件会由发布者接收。以下分别说明这些数据如何处理。

1. 适用范围

本政策适用于“我全都要 WantSave”1.1.0 Chrome 基础版、本隐私政策网站，以及你通过支持邮箱向 WantSave 提交的问题。基础版提供网页视频、音频与图片保存、支持的音视频合并和本地下载任务恢复。

当前基础版没有扩展账号、购买、订阅、广告、遥测或本地 agent/MCP 联动。仅保存你有权下载的内容；原网站的访问条件和隐私政策仍然适用。

2. 扩展会处理的数据

  • 网页和媒体信息：当前网页及相关框架的地址、标题、媒体元素、媒体链接、播放列表、播放信息和可用画质。
  • 媒体网络响应：用于识别媒体的请求地址、来源框架、响应类型、文件名、文件大小、来源地址和发现时间。
  • 本地下载任务：任务标题、必要的规范来源信息、所选画质、状态、进度、时间和下载记录标识，以及完整取得的媒体流、片段或合并文件缓存。
  • 设置：是否在视频附近显示下载按钮，以及自动、中文或英文语言偏好。

这些数据用于发现和保存媒体、展示任务、检查保存状态及恢复任务。页面下载按钮开关只控制页面入口；后台媒体发现仍可能在获授权网页运行。你可通过 Chrome 的扩展管理页面限制网站访问或禁用扩展。

3. 本地存储、保留与删除

按钮和语言设置存储在当前 Chrome 配置的本地扩展存储中。网络媒体候选和部分含临时参数的来源记录保存在浏览器会话存储中；相关媒体候选在页面导航或关闭后清理，会话数据会在浏览器会话结束时清理。

任务记录和媒体缓存保存在扩展本地数据库中，供关闭任务页或重启 Chrome 后恢复使用，并保留至你在“任务列表与恢复”中清除任务。临时链接失效或含查询参数的来源未保留时，恢复可能需要重新获取或重新提供链接。尚未完整取得的流或片段会重新下载。新增站点的临时媒体来源只在当前浏览器会话保留；重启后未完成的任务可能需要回到原网页重新添加。

清除任务和缓存不会删除已经保存到电脑的文件。磁盘文件与 Chrome 下载记录由你通过系统和浏览器管理。卸载扩展或清除扩展数据会使本地设置和缓存不可用。

4. 与原网站和媒体服务器的通信

下载直接请求你选择的原网站、播放列表及其媒体分发服务器。Bilibili 和 YouTube 发现功能还会访问原站公开页面和播放信息接口。YouTube 适配读取当前网页的公开播放器配置，通过随包提供的代码调用已加载播放器的地址转换功能；不会执行下载得到的脚本。YouTube 原站播放信息请求使用浏览器的正常站点上下文。这些服务会接收完成请求所需的信息，例如 IP 地址、请求地址和请求头，并按其自身政策处理。

扩展不直接读取、保存或导出浏览器 Cookie。部分原站请求可能由 Chrome 根据站点和隐私设置自动附带已有凭证。所选资源的网络协议取决于原地址；扩展没有独立的登录、密码或支付收集表单。

5. 数据用途与共享

扩展不会把媒体、下载任务或浏览活动上传到发布者运营的数据收集服务，不使用 Chrome 同步存储。WantSave 不出售这些数据，不将其用于广告、信用评估、贷款或与媒体下载和本地任务恢复无关的目的。提供下载功能所需的原站通信见上一节。

WantSave 对通过 Chrome 接口取得的信息的使用遵循 Chrome Web Store User Data Policy，包括其 Limited Use（有限使用）要求。

6. 本网站与 GitHub Pages

本网站为 GitHub Pages 托管的静态网页。网站没有由 WantSave 添加的统计脚本、广告、跟踪像素或登录功能。根据 GitHub 的说明，访问 GitHub Pages 时，GitHub 会为安全目的记录和保存访问者 IP 地址；这与扩展的本地媒体处理是两项独立的数据处理。

详见 GitHub Pages 数据收集说明和 GitHub 隐私声明。

7. 支持邮件

如果你主动给支持邮箱发邮件，WantSave 会收到你的发件地址、邮件内容及你自行附加的信息，用于答复和处理该问题。邮箱服务商也会按其政策处理邮件。支持邮件在处理问题及必要后续沟通所需期间保留，你可通过下方邮箱提出删除请求。

反馈通常只需提供扩展版本、操作步骤和错误提示。请勿附上密码、验证码、私人媒体或带访问令牌的完整链接。

产品或数据处理方式发生变化时，WantSave 会更新本政策和页面日期，并同步相应的商店隐私披露。有关本政策、数据处理或支持邮件删除的问题，请联系：

WANTSAVE · CHROME BASIC EDITION 1.1.0

Privacy policy

Publisher: WantSave · Effective: October 20, 2026 · Updated: October 21, 2026

WantSave finds, downloads and merges media in your browser and stores local tasks for recovery. The extension has no publisher-operated media upload or activity analytics service. This website is hosted on GitHub Pages, and the publisher receives support emails you choose to send. These separate uses are explained below.

1. Scope

This policy covers the WantSave 1.1.0 basic Chrome extension, this privacy policy website and questions you send to WantSave's support email. The basic edition saves web videos, audio and images, merges supported media in the browser and provides local download task recovery.

The current basic edition has no extension account, purchases, subscriptions, advertising, telemetry or local agent/MCP integration. Save only content you have the right to download. The source website's access conditions and privacy policy still apply.

2. Data handled by the extension

  • Page and media information: addresses and titles of the current page and relevant frames, media elements and links, playlists, playback information and available qualities.
  • Media network responses: request URLs, source frames, response types, filenames, file sizes, referring sources and detection times used to identify media.
  • Local download tasks: titles, necessary normalized source information, selected quality, status, progress, timestamps, download record identifiers and cached complete media streams, segments or merged files.
  • Settings: whether download buttons appear near videos, and automatic, Chinese or English language preferences.

This information supports media discovery and saving, task display, download completion checks and task recovery. The in-page button setting controls the page entry point; background media discovery can still run on authorized pages. You can restrict website access or disable the extension through Chrome's extension settings.

3. Local storage, retention and deletion

Button and language preferences are saved in the current Chrome profile's local extension storage. Network media candidates and some source records containing temporary URL parameters use browser session storage. Relevant media candidates are cleared when pages navigate or tabs close, and session data is cleared when the browser session ends.

Task records and media caches use the extension's local database so tasks can be recovered after closing a task page or restarting Chrome. They remain until you clear the task through the task list. Recovery may require refreshing or supplying a source URL again when a temporary link expires or its query parameters were not retained. Incomplete streams or segments are fetched again. Temporary sources used by new site adapters remain only in the current browser session; an unfinished task may need to be added again from its original page after restarting.

Clearing tasks and caches does not delete files already saved to your computer. You manage disk files and Chrome download history through your operating system and browser. Uninstalling the extension or clearing its data makes its local settings and caches unavailable.

4. Requests to source websites and media servers

Downloads request the source website, playlist and media distribution servers you select. Bilibili and YouTube discovery also request public original-site pages and playback metadata. The YouTube adapter reads public player configuration from the current page. Bundled code calls the already-loaded player URL conversion function; downloaded scripts are never executed. YouTube playback-metadata requests on the original site use the browser's normal site context. These services receive information needed for the request, such as your IP address, request URL and headers, and process it under their own policies.

The extension does not directly read, store or export browser cookies. Chrome may attach existing credentials to some source-site requests according to site and privacy settings. The resource's network protocol depends on its original URL. The extension has no separate form for collecting logins, passwords or payment details.

5. Use and sharing

The extension does not upload media, download tasks or browsing activity to a publisher-operated data collection service and does not use Chrome sync storage. WantSave does not sell this data or use it for advertising, creditworthiness, lending or purposes unrelated to media downloading and local task recovery. Requests needed to deliver downloads are described in the previous section.

WantSave's use of information from Chrome APIs follows the Chrome Web Store User Data Policy, including its Limited Use requirements.

6. This website and GitHub Pages

This is a static website hosted on GitHub Pages. WantSave has added no analytics scripts, advertisements, tracking pixels or login feature to the site. GitHub states that it logs and stores visitors' IP addresses for security when GitHub Pages sites are visited. This is separate from the extension's local media processing.

See GitHub Pages data collection and the GitHub Privacy Statement.

7. Support email

If you choose to email support, WantSave receives your sender address, message and any information you attach to answer and resolve your request. The email provider also processes messages under its own policy. Support correspondence is retained for as long as needed to handle the request and necessary follow-up. You can request deletion using the contact address below.

An issue report normally needs only the extension version, steps and error message. Please leave out passwords, verification codes, private media and complete links containing access tokens.
